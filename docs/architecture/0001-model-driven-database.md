# ADR 0001: INTERLIS als fachliche Source of Truth

## Status

Accepted for Phase 0.

## Context

Mabillon exchanges durable GEVER data and must keep database persistence,
transfer data, and generated persistence mappings consistent. A hand-maintained
database schema would make the INTERLIS model and the running database diverge.

## Decision

The model in `model/SO_AGI_GEVER_20260707.ili` is the source of truth for
persistent domain structure. The reproducible pipeline is:

```text
INTERLIS -> ili2c -> ili2pg schemaimport -> PostgreSQL -> Cayenne DB Import/cgen -> Java
```

Schema creation and XTF import are centralized in `scripts/create-schema.sh`
and `scripts/import-xtf.sh`. Fachliche DB-Spalten are not introduced directly
through Flyway or handwritten SQL. Technical application tables may be placed
in `mabillon_app` only where the specification explicitly permits them.

## Consequences

- Every model change is compiled with the pinned ili2c tool before schema work.
- Positive XTF data is validated with the pinned ilivalidator before import.
- PostgreSQL constraints and transfer metadata are generated by ili2pg.
- Model evolution requires a fresh schema/mapping verification and a reviewed
  generated-code diff.
